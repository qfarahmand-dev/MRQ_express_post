MRQ Express Post - معرفی ساختار و قابلیت‌های پروژه
===================================================

هدف پروژه
---------
وب‌سایت خدمات پستی و حمل‌ونقل MRQ Express Post است. بازدیدکننده می‌تواند
اطلاعات عمومی سایت را ببیند و مرسوله را با شماره رهگیری جست‌وجو کند.
مدیر وارد داشبورد می‌شود تا مرسوله‌ها، وضعیت آن‌ها و اطلاعات حساب را مدیریت کند.

فناوری‌های اصلی
---------------
- Next.js 16 و React 19 برای رابط کاربری و مسیرهای وب
- TypeScript برای نوع‌دهی کد
- Supabase Auth برای ورود و مدیریت نشست مدیر
- Supabase PostgreSQL برای اطلاعات مرسوله‌ها و رویدادهای وضعیت
- SWR برای دریافت و تازه‌سازی داده‌های سمت رابط کاربری
- Tailwind CSS و اجزای UI برای طراحی
- پشتیبانی از فارسی و انگلیسی، همراه با چینش راست‌به‌چپ فارسی
- Vercel برای میزبانی برنامه

قابلیت‌های پیاده‌سازی‌شده
------------------------
1. بخش عمومی
   - صفحه اصلی معرفی خدمات
   - فرم جست‌وجوی شماره رهگیری و نمایش روند مرسوله
   - صفحه ورود مدیر، همراه با پیوند بازگشت به وب‌سایت

2. داشبورد مدیر
   - نمایش آمار، مرسوله‌های اخیر و آخرین به‌روزرسانی‌ها
   - فهرست، جست‌وجو و فیلتر مرسوله‌ها
   - ثبت، مشاهده، ویرایش و حذف مرسوله
   - تغییر وضعیت مرسوله و ثبت تاریخچه، محل و یادداشت
   - مشاهده و ویرایش نام و ایمیل پروفایل
   - تغییر رمز عبور با واردکردن رمز فعلی و تأیید دوباره رمز جدید
   - خروج از حساب و بررسی نشست هنگام برگشت به صفحه داشبورد

3. نقش و دسترسی
   - تنها نقش برنامه «admin» است.
   - ثبت‌نام عمومی در فرانت‌اند وجود ندارد.
   - ایمیل مدیر باید در admin_allowlist دیتابیس مجاز شده باشد.
   - مسیرهای داشبورد نیازمند نشست معتبر و پروفایل admin هستند.

4. اتصال و امنیت داده
   - سرویس‌های احراز هویت و مرسوله به Supabase متصل شده‌اند.
   - داده‌های مرسوله از پایگاه‌داده خوانده و در آن ذخیره می‌شوند، نه فقط در حافظه مرورگر.
   - تاریخچه وضعیت مرسوله در جدول جداگانه ثبت می‌شود.
   - RLS برای جداول تعریف شده است تا دسترسی داده‌ها از سمت دیتابیس کنترل شود.
   - رهگیری عمومی از تابع محدود track_shipment استفاده می‌کند و شماره تماس و نشانی
     کامل را به بازدیدکننده برنمی‌گرداند.
   - از کلید publishable در مرورگر استفاده می‌شود؛ کلید service_role نباید وارد
     فرانت‌اند یا فایل‌های قابل انتشار شود.

راه‌اندازی‌های لازم در حساب‌های بیرونی
--------------------------------------
کد پروژه به Supabase و Vercel آماده اتصال است، اما این فایل‌ها به‌تنهایی
پیکربندی حساب‌های بیرونی را انجام نمی‌دهند:

1. فایل supabase/migrations/20261112000000_initial_schema.sql را یک‌بار در
   SQL Editor پروژه Supabase اجرا کنید.
2. ایمیل مدیر را در جدول admin_allowlist ثبت کنید.
3. ثبت‌نام عمومی Supabase را خاموش کنید و حساب مدیر را در Authentication
   ایجاد یا دعوت کنید.
4. متغیرهای زیر را با مقادیر پروژه خود در .env.local و تنظیمات Vercel قرار دهید:
     NEXT_PUBLIC_SUPABASE_URL
     NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
   فایل .env.local محرمانه است و نباید commit یا برای دیگران ارسال شود.
5. دامنه Vercel را در تنظیمات URL احراز هویت Supabase ثبت کنید.

داده‌های mock در data\mock-shipments.ts و data\mock-users.ts نمونه‌های باقی‌مانده
از نسخه نمایشی هستند؛ سرویس‌های فعال از آن‌ها برای ذخیره یا خواندن اطلاعات
واقعی استفاده نمی‌کنند. دیتابیس جدید تا زمان ثبت مرسوله‌ها خالی خواهد بود.

وضعیت بررسی
------------
- بررسی TypeScript با موفقیت انجام شده است.
- ساخت production برنامه با Next.js موفق بوده است.
- اجرای واقعی مهاجرت و تبادل داده با پروژه Supabase یا انتشار در حساب Vercel
  فقط پس از تنظیم و تأیید آن حساب‌ها قابل بررسی است.
